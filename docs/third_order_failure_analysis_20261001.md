# 三阶修正为何尚未产生可重复收益：代码与已有日志审查

日期：2026-10-01。按用户要求停止模型实验；本次仅阅读代码、对照已有日志、做标量计算，没有启动第三轮或新的 GPU 实验。

## 结论与证据边界

最明确的方法限制是：**当前实现修正了梯度中关于残差的偶次部分，却继续用原来的 Fisher 近似奇次部分；原先的二阶曲率近似误差仍然保留。** 因此，“加了三阶”不能推出“整个梯度已经足够准确”。已有局部审查显示方向有所改善，但 gate_proj 的相对梯度误差几乎没变。

这解释了方法为什么没有必然收益，但目前不能给各种原因分配因果占比。真实下游梯度经过权重 Jacobian、坐标裁剪、Adam 和后续离散量化后发生了什么，旧日志没有完整记录，不能把最终 KL 回退全部归因于某一个环节。

还要纠正结果表述：原 attention 后端三次候选的平均 KL 回退；改用 math-SDPA 后有一组 KL 改善 2.25% 的配对结果，但其重复运行被停止，没有最终指标。因此是“没有建立可重复收益”，不是“所有实验都没有改善”。

## 1. 当前公式没有修复 Fisher 的低阶误差

记 `d = yq - y0`，`g+`、`g-`、`g0` 分别为固定 FP 后缀的 KL 在 `y0+d`、`y0-d`、`y0` 的输出梯度；`gF` 是代码实际算出的 Fisher loss 输出梯度。对应实现：`gptq_utils/gptq_plus_utils.py:10268–10344`。

实现的公式是：

```text
gc = g0 + gF + (g+ + g- - 2*g0)/2
   = gF + (g+ + g-)/2

gc - g+ = gF - (g+ - g-)/2
```

这是代数恒等式，忽略浮点加减舍入后成立，不要求残差很小，也不要求 g0 为零。它说明剩余误差恰好是：**Fisher 梯度，与真实梯度的中心奇次部分之间的差**。g0 在公式中抵消并不是漏掉一阶项的代码 bug；参考梯度已包含在两侧梯度的平均中。

为了理解阶数，将整段序列输出展平；把 token 平均等归一化吸收到有效算子 F、H 中。在光滑、精确对称采样的理想情况下：

```text
g(y0+d) = g0 + H d + (1/2) T[d,d]
                    + (1/6) D4L[d,d,d] + ...
gc       = g0 + F d + (1/2) T[d,d] + O(||d||^4)
gc-g+    = (F-H)d - (1/6) D4L[d,d,d] + O(||d||^5)
```

`T = D3L`。加入的三阶损失修正，对梯度的贡献是 `O(||d||²)`；留下的 `(F-H)d` 则是 `O(||d||)`。如果低阶曲率本来就没有拟合好，仅补高阶项不能系统性消除这个误差。这里的 F 指项目的有限采样、跨 token 聚合的 Fisher 代理，不是在否定“匹配参考分布处完整 Fisher 与 KL Hessian 的对应关系”。

BF16 下负向点经过舍入，不能严格套用上述对称 Taylor 阶数；但用实际计算出来的 g+、g-，前面的代数误差恒等式依然成立（浮点舍入除外）。旧日志没有保存完整 g- 张量，无法进一步离线测出各阶误差的占比。

## 2. “方向更接近”距离“梯度足够准确”还有差距

使用 math-SDPA 完整候选的 `THIRD_ORDER_GRAD_AUDIT` 日志。每个模块只记录第一次 refresh 的第一个 batch（4 条样本），并非全部 32 条校准样本和全部更新。

从日志中的范数和余弦可直接计算：

```text
relative_error(a,g) = ||a-g|| / ||g||
                   = sqrt(1 + r*r - 2*r*cos(a,g)), r=||a||/||g||
```

| 模块 | Fisher→真实梯度余弦 | 修正→真实梯度余弦 | Fisher 相对误差 | 修正相对误差 | 修正/真实梯度范数 |
|---|---:|---:|---:|---:|---:|
| up_proj | 0.00033 | 0.468 | 1.27 | 1.00 | 0.93 |
| gate_proj | −0.00069 | 0.192 | 2.05 | 2.01 | 1.94 |
| down_proj | −0.00013 | 0.634 | 1.12 | 0.78 | 0.71 |

这些数据证明局部输出梯度有所改善；尤其 gate 的误差仍非常大。它们不能证明修正后的权重更新会降低真实 KL。

此外，`tests/test_third_order_taylor.py` 的正向 toy case 使用**真实 HVP**作为二阶基础，并在小扰动上验证三阶修正；正式 REAL-Q 分支使用的是**聚合 Fisher 梯度**作为基础。这两者不是同一个精度前提。toy test 通过，不等于生产集成的代理梯度已被验证。

## 3. 有哪些实现问题，哪些目前没有证据

### 已确认的观测缺口

* `gptq_plus_utils.py:10404–10415` 用 detached 的线性项注入候选梯度，同时保留原 Fisher loss 的前向数值。因而 `loss`/`loss_cur` 是原代理的数值，**不是三阶修正目标的数值，也不是真实 KL**。这不阻断候选梯度，但不能从这些标量得出“修正 loss 更小”的结论；浮点加减还可能引入很小的数值舍入。
* 梯度先经实际 block Jacobian 映射到权重，再经过样本聚合、可更新列切片、逐坐标裁剪和 Adam 矩归一化（`10478`、`10489`、`2826–2864` 附近）。输出空间余弦改善不会自动保留到最终更新向量。当前日志的更新统计多为 `None`，不能断言 Adam 抹掉了收益，也不能排除。
* 只改变第 4 层 FFN 的 Adam 梯度，不改变 GPTQ 闭式解、量化格点或已量化列。这限制了它能干预的环节，但不证明真正瓶颈一定在其他环节。

### 本次没有发现的明显错误

* Fisher loss 具有 `0.5` 因子，沿 hidden 维求和、对 batch/token 求平均；真实 KL 同样对 token 求平均。样本梯度聚合先乘 batch 大小再统一归一化。所查路径没有发现简单的“漏乘 2”或“把求和当平均”的实现错误。
* Fisher 预计算的 loss scale 为 1000，梯度外积除回 1000²，随后除 token 数；没有看到忘记撤销该 scale 的错误。这不等于经验 Fisher 在统计上准确。
* 本组设置 `a_loss_ratio=1.0`、`slide_window=False`、未忽略 attention sink，没有这些额外变换混入上述梯度比较。

### 只能列为假设的因素

* 实际残差 `||d||/||y0||≈0.41–0.43`，同时包括前缀误差和当前 block 误差。中央差分直接使用这个有限步长，因此不是纯粹的三阶导数估计；对称梯度平均还含残差四次等高次项。但**仅凭相对残差不能证明 Taylor 已失效**，还需方向上的高阶变化或余项证据。
* BF16 位置不对称约 0.24–0.41%。它较小，但没有梯度敏感度界，不能据此排除数值误差是重要原因。
* “真实梯度”对应的是**当前固定 FP 后缀**；最终模型的后缀还要量化。目标不一致确实存在，但是否主导 KL 回退没有因果证据。旧后端直接使用该真实梯度的三次诊断平均 KL 也回退 1.39%，说明单纯提高这一局部梯度精度并未保证最终收益；它并不能单独证明是后缀问题，也不是最终质量的上界。

## 4. 重复性重新核对

旧后端中，deterministic 配置没有调用已有的 math-SDPA helper，且采用 `warn_only=True`；日志出现非确定性 attention backward 警告。候选确实有运行间差异，但不能在未排除其他因素时把全部差异归因于此。

本次逐条对比两次 math-SDPA 候选的 `block-metrics` 行，去除时间戳后：

* 完整候选 2,044 条；停止的重复候选 2,000 条。
* 共同的 2,000 条在**日志打印精度**下全部一致，3 条首批梯度审查也一致。
* 这比仅首批审查一致的证据强，但不是权重/输出 bitwise 一致证明，且第二次没有最终 KL/PPL。

math-SDPA 配对的 KL 从 `0.2359349728` 到 `0.2306290865`（−2.25%），PPL 从 `33.28921127` 到 `32.81828690`；单次总时长从 15m36s 到 25m24s（约 +63%）。它是该后端的一组正向结果，不能跨后端与旧 baseline 混比，也不能因为它使用 math 后端就直接判为无效。

后续写入 `ptq.py` 的 teacher/eval 默认 SDPA、量化 math-SDPA 分阶段切换尚未完整验证，不属于上述完成实验的结果。本次不修改训练代码，也不启动该配置。

## 5. 当前决定

不跑第三轮，不扩大到更多层，也不通过挑选单次指标或调系数宣称 work。

目前能成立的是：当前三阶方案保留了 Fisher 的低阶误差，局部改善有限且不均匀，同时缺少从输出梯度到最终 Adam 更新的证据链。不能把失败简单归结为“三阶没有用”“SwiGLU 太非线性”或“都是随机误差”。若将来继续，需要先补齐二阶基础与实际更新效果的机制证据；本报告不代表批准重启实验。
