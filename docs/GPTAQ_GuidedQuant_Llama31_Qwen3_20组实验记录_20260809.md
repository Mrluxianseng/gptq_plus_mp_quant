# GPTAQ / GuidedQuant：Llama-3.1 与 Qwen3 20 组实验记录

> 本文档是本轮 GPTAQ / GuidedQuant 实验的唯一进度账本。时间均为 Asia/Shanghai。

## 冻结范围

- 模型：Qwen3-0.6B、Llama-3.1-8B-Instruct、Qwen3-4B、Qwen3-8B、Qwen3-32B。
- 每模型四种设定：W4A16、W4A4KV4、W3A16、W2A16，共 20 组。
- 方法：GPTAQ 与 GuidedQuant（本地入口名 `guided_gptq`），各 20 组，共 40 个正式量化 checkpoint。
- 量化协议沿用《低比特激活值实验记录》冻结 baseline：单卡 L20C；WikiText-2 train 256×2048/seed1；weight group/block=128；symmetric MSE clipping；act-order；QuaRot/rotation_seed=0；关闭 input offload；GPTAQ alpha=0.25。
- W4A4KV4 开启 A/K/V-aware 且 clip=0.9；三种 A16 设置保持 weight-only、A/K/V=16、clip=1.0。
- Guided 每模型只生成一次 4 组 saliency/Fisher producer；梯度在平方前乘 1e3，组内 squared Euclidean sum，使用共享未加权 input-energy act-order。producer 完整验证层数、模块键、[256,2048,4] shape、BF16 与 finite 后才放行消费者。
- 每个正式 checkpoint 评测 WikiText-2 Exact KL/PPL、论文十项 QA、GSM8K、MATH-500、HumanEval+，HumanEval+ 必须完成官方 EvalPlus 判分。
- 量化 GPU-hour 使用 `algorithm_core_v1`：含 rotation 与 quantization core，不含模型加载、checkpoint 保存及所有评测。

## 资源与执行方式

- 严格按 `AGENT.md`：复用两个 8 卡长 sleep debugging job，通过 SSH 在 Pod 内执行，不把高负载放在宿主机。
- node0：`j-p1agegu8nh`（当前 retry1，节点 `e01-cn-rij4mvgjj0i`）。
- node1：`j-xz8xghpcqh`（当前 retry0，节点 `e01-cn-8h74p0pxk0t`）。
- 两节点启动前均确认 8/8 GPU 无 CUDA 进程。
- 40 个量化组按节点各 20 组固定分配；Qwen3-32B GuidedQuant 在两节点各 2 组，避免单节点长尾。

## 缓存与恢复约束

- 复用已通过 REAL-Q 20 组终审的同一 WikiText-2 calibration tokens 与量化协议 BF16 reference logits，只创建指向不可变源文件的链接，不重新生成、不并发写缓存。
- Guided saliency 使用本轮独立 attempt-local 目录生成；验证和稳定性检查通过后才发布 canonical 链接。
- 正式 checkpoint 先写在 attempt-local 路径，稳定后发布 canonical 链接。若 checkpoint 后的 PPL/QA 失败，只从 checkpoint 重载评测，不重复量化。
- QA OOM 只允许降低 `lm_eval_batch_size`（32→16→8→4→2→1），不改变量化参数。
- 两个 node controller 每 30 秒写 heartbeat，失败项保留 traceback 与 attempt，最多自动重试三次；进度由主代理每五分钟同时核验控制面、heartbeat、日志和逐卡占用。
