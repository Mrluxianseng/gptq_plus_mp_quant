# 一种面向 REAL-Q 量化的存储管理优化方法：贡献整理 v1

整理日期：2026-10-12。本文用于形成论文方法章、贡献表述和后续消融设计。它整理已有实现和已验收证据，不新增实验结果，不替代最终研究报告。1.7B低扰动时间成本仍待预定配对完成。

## 1. 研究问题与一句话主张

**面向 REAL-Q 的求逆—分组量化与梯度刷新—激活回放执行链，依据张量最后消费者和存储别名约束，联合安排工作区复用、已消费 Hessian 存储复用、稳定权重写回和阶段边界释放，在保持原量化计算与结果的条件下降低全流程显存峰值。**

研究对象是本仓库 REAL-Q 实现中已经验证的顺序分组路径。优化发生在 GPU 内部存储分配与对象持有关系上；求逆仍在 GPU 上以 FP32 计算，模型原权重为 BF16。既有输入卸载、checkpoint、CE分块属于比较基线。本文不改变校准数据、seed、量化位宽、损失、Adam或学习率。

[REAL-Q原论文](https://arxiv.org/abs/2609.00049v2)将细粒度块梯度修正作为量化机制之一。本工作保留该计算顺序与更新规则，研究其实现过程中哪些存储必须继续保留、哪些存储可以被后续结果接管。原论文的精度收益不属于本文方法贡献。

目前可以成立的是“特定实现与配置下的存储管理方法及其验证”。“首创”“通用最优调度”“跨所有REAL-Q设置成立”尚不能由当前资料推出。

## 3. 问题形式化与正确性条件

将原执行序列记为 E=(e₁,…,eₖ)。对逻辑张量 x 记录最后消费者 d(x)、dtype、shape、stride、存储别名集合和必须保留的值。方法保持 E 的数学操作顺序，改变允许的存储映射与释放位置。

理想化活跃存储需求记为 A(t)=Σ size(s)，其中 s 遍历时刻t所有必须存活的**不同存储**，而不是所有Tensor对象；共享存储的view不得重复计数。A(t)用于解释复用机会，不等同于PyTorch实测allocated：求解器内部工作区、分配粒度与其他运行时对象还需实际测量。reserved还取决于缓存分配器历史与段布局，NVML还包含进程外及非PyTorch开销。因此不从A(t)直接推导reserved/NVML下降。

设计目标是降低原执行链的全流程峰值，且实际 full-process allocated、reserved及全设备NVML采样峰各不高于相同工作量control；并保留区间与起终点变化。实现是带条件的确定性存储策略，不是求解全局最优调度的ILP算法。

允许复用或释放须满足以下条件：

1. 旧内容的所有必要消费者已结束；在CUDA执行上还须符合所在流与分配器的顺序要求，不能将Python返回等同于任意跨流计算已经完成。
2. 新输出有足够且兼容的存储，dtype/shape/stride保持原计算需要；单个求解算子的输入与out目标不重叠。
3. 仍需保留的因子、未处理子组和回放权重不得被覆盖。释放私有输入时检查它没有与保留因子共享存储。
4. 阻尼重试从原私有H输入重新构造，保留原回退与有限性检查；不通过改变精度或数学操作减少显存。
5. 权重写回发生在原更新图已消费的边界；保持Parameter对象、目标dtype与形状，验证实际存储指针保持。
6. 统计释放位于原after_layer_quantized hook之后；AST核对后续无消费者与重绑定。现有源码的此项核对不是任意Python程序的通用别名证明。

上述条件说明每次存储变换为何允许，不构成所有配置下浮点逐位一致的普遍定理。当前数值一致性由真实路径实验独立检验。

## 4. 核心机制与实现对应

### 4.1 两工作区求逆与已消费H接管因子

原求解器按相同顺序执行下三角Cholesky、Cholesky逆、逆矩阵上三角Cholesky。方法在首个分解完成后将不再读取的H_work作为逆矩阵out目标；在求逆完成后将不再读取的chol作为最终因子out目标。布局用原因子的stride解释同一存储，各算子保持输入与输出存储分离。

随后，在当前子组原H已无消费者的条件下，将最终因子复制到self.H[sub_idx]对应存储，并保留原因子的shape/stride供后续量化使用。未消费的其他子组H保持原内容。两工作区解决算子间的短期重叠，H接管解决因子跨子组/量化阶段的持有；它们针对不同存活区间。

实现依据：[工作区](../tools/hessian_solver_workspace_prototype.py)、[已消费H复用](../tools/hessian_inverse_lifetime_prototype.py)。当前H复用限制down_proj、alpha=0、无Hessian正则、无H/Hinv CPU offload及已验证顺序路径；工作区遇到inplace_damping调用使用原helper。条件外不能假报优化覆盖。

### 4.2 down权重稳定写回

原final写回通过FP32结果转回权重原dtype并替换weight.data存储。方法在down_proj的现有目标存储中copy_同一结果，保持目标dtype转换，并避免创建新的长期权重分配。要求目标连续、device和shape兼容；当前刷新图已在原写回点被消费。

实现依据：[稳定写回](../tools/hessian_stable_weight_prototype.py)。每层观察实际指针、dtype、stride和bytes；Parameter身份和存储指针属于不同层面的约束。其设计动机是避免新权重占用求解临时段，但目前没有证明某一次reserved回升由这一原因唯一导致。

### 4.3 末组私有输入与回放统计的阶段边界释放

子组准备完成后，最后一个私有H_sub仍可能被fasterquant局部变量持有。方法在求解与诊断最后消费者之后、块量化/刷新之前释放该私有输入，保留subgroup_states中的不可变因子，并拒绝输入与保留因子的存储别名。

整层量化完成后，GPTQPlus.free清除H/Losses不代表所有统计所有者已经解除。方法将原del gptq及saliency_dict/gradients_dict删除移到after_layer_quantized hook之后、激活回放之前，避免死统计与回放活跃张量同时存活。共享观察器只保存CPU整数，不延长GPU Tensor寿命。

实现依据：[私有H死亡点](../tools/hessian_dead_subgroup_input_prototype.py)、[统计死亡点](../tools/activation_replay_stats_lifetime_prototype.py)、[统计接入](../tools/activation_replay_stats_install.py)。48.0234375MiB/层（1.7B）及12.01171875MiB/层（0.6B）是观察到的统计持有量，不是各自全流程峰值降低量。

```mermaid
flowchart LR
    A[当前子组H输入] --> B[求逆工作区复用]
    B --> C[最终因子接管已消费H存储]
    C --> D[全部子组准备结束]
    D --> E[释放末组私有H输入]
    E --> F[原块量化与梯度刷新]
    F --> G[down权重稳定写回]
    G --> H[整层量化hook结束]
    H --> I[释放死统计对象]
    I --> J[原激活回放与层清理]
```

该图是消费边界示意，不表达所有真实调用、释放或CUDA同步细节。精确顺序以冻结实际入口和调用元数据为准。

## 5. 方法为什么需要联合设计

减少求解器短期矩阵同时存活，不保证后续回放阶段reserved也下降；权重存储位置与统计持有还会影响分配历史。旧workspace组合在1.7B全局峰下降时仍有layer3/10回放reserved+36MiB；后续earlystats组合消除此现象。这支持阶段间存储状态需要联合考虑，但不足以确认+36MiB的唯一分配根因或统计释放的独立全局降幅。

0.6B简方案每对仍有layer25局部reserved+96MiB，同时全局allocated/reserved/NVML下降。compact池方案获得局部零回升，却未进一步降低allocated/NVML，且其candidate全局reserved从简方案3362增至3394MiB。因而论文应围绕全流程容量效果选择方法，不能以每个局部点更低替代硬件容量结论。

## 6. 已有证据与可写结论

相对已包含checkpoint与CE分块的control，同一简方案双模型各三对fresh Stage0+28层量化+评估，容量结果如下。统计单位为MiB。

| Qwen3-1.7B | 5605.190918→4883.690918（−12.872%） | 5872→5332（−9.196%） | 6629→6089（−8.146%） |
| Qwen3-0.6B | 3151.033691→3010.087402（−4.473%） | 3490→3362（−3.668%） | 4247→4119（−3.014%） |

[六对完整独立汇总](../outputs/two-model-hardware-capacity-accepted-20261012-v1/summary.json)逐对涵盖507state、全部28层非空输出、KL/PPL、完整源码/13文件缓存SHA、真实112次down求逆/复用及28次写回/死亡点/统计观察。累计17766对应区间和71064独立起终点allocated/reserved值。0.6B每对1个区间和2个point局部+96MiB保留，原strictFalse未覆盖；11:15主验收转为全局硬件容量。

[纯求逆归因](../outputs/hessian-peak-attribution-20261011-v1.json)约4018→3298MiB是该记录中的纯求逆区间结果。after_hessian_inverse标记之后还含量化/梯度刷新，约5027MiB后续峰不能全归为纯求逆。组件峰、特定区间峰与full-process峰不能互换。

当前是RTX4060 Laptop 8GB上的cal2×1024 pilot。NVML是采样而非连续每刻证明。“降低当前工作量全流程显存峰值”已获支持；“扩大到某个更大任务或更小GPU的可运行范围”仍待实际边界实验，不写成现有成果。

[0.6B三对低扰动成本](../outputs/replay-stats-low-overhead-cost-20261012-v3/independent_three_pair_qwen06_summary-20261012-1655.json)显示量化均值970.274533→1095.378822秒（+12.8937%），一快两慢。时间作为代价报告，未证明稳定加速或唯一波动原因；collector+quant不含准备/评估/hash，且保留CPU观察。1.7B三对成本待完成，不用历史dense插桩时间替代。

## 7. 原创性边界与相关工作

| 依据 | 与本方法的关系 | 不能归给本方法的内容 |
| --- | --- | --- |
| [REAL-Q](https://arxiv.org/abs/2609.00049v2) | 保留被优化对象的块梯度修正及量化规则 | REAL-Q的量化数学、精度提升和滑动机制 |
| [OLLA](https://arxiv.org/abs/2210.12924v2) | 已有张量寿命与存储位置联合优化思想；本文针对REAL-Q固定执行链具体化 | 生命周期/存储复用思想本身、OLLA的ILP求解器或其最优性 |
| [Checkmate](https://arxiv.org/abs/1910.02653v3) | 支持显存与计算时间权衡的评价视角 | 通用重计算/checkpoint思想、其最优重计算调度算法 |
| [PyTorch CUDA语义](https://docs.pytorch.org/docs/2.11/notes/cuda.html)与版本绑定allocator源码 | 提供缓存分配、存储复用和流顺序的实现约束 | 原生allocator创新、未实施的全局碎片整理 |

本文候选贡献在于：针对REAL-Q真实消费者和存储别名，构造求逆至回放的受限复用/释放方案并验证数值与全流程容量。一般性del、out=、copy_本身是已知操作。本文不是新的Hessian近似、CPU求逆或降精度量化，也没有实现OLLA/Checkmate求解器。已核对上述主文献，但这不等同于完成穷尽式创新性查新；定稿前仍需比较REAL-Q官方实现和其他量化系统的相关存储策略。

不列入核心贡献的工程支撑包括：checkpoint、CE分块、已有输入卸载、工件只读hardlink、进程恢复、记录包装修复、SHA与审查器。负向finite/all-linear/大小policy/compact池保留为选择依据和局限，不混入简方案重复次数。

## 9. 可用于论文的贡献表述草稿

“针对REAL-Q量化中求逆中间量、保留因子与回放统计的存活重叠问题，本文设计一种依据张量最后消费者与存储别名约束的存储管理方法。该方法在保持原计算顺序与精度的条件下，通过求逆工作区复用、已消费Hessian存储接管、量化权重稳定写回与阶段边界释放，减少不必要的同时存活存储。对Qwen3-0.6B与1.7B的初步实验表明，方法保持量化state、层输出及KL/PPL一致，并降低全流程显存峰值；论文同时分析局部分配变化与运行时间代价。”
