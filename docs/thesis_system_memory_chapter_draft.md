# REAL-Q 系统显存优化：终稿章节工作稿

本文是工程设计及实验论证的工作稿，不是已经完成全部正式实验的终稿。数值只引用已审计的运行；重复次数、多卡和正式校准规模没有完成的地方保持待测状态。持续实验记录以 `memory_speed_optimization_journal.md` 为准。

## 研究问题与工程边界

REAL-Q 在预计算阶段收集 Fisher 与 saliency，在量化阶段结合闭式补偿和局部梯度更新。它需要的 GPU 工作集同时受模型结构、校准序列、词表以及临时矩阵生命周期影响。仅减少一个模块的临时量，并不一定降低整个量化工作流的硬件门槛；当原瓶颈消除后，最大值可能转移到其他阶段。

本研究以保持既有量化结果为约束，管理张量的存放位置、共享副本和生命周期。研究对象是校准和量化的 GPU 资源需求，最终评估也纳入完整工作流测量。评估显存的改进不能代替量化阶段的工程贡献。本文不改变 Fisher 损失、Adam 公式、量化位宽、补偿顺序或校准数据来获取质量收益。

一套系统实现可以包含多个相互配合的工程组件，但组件数量不等于论文贡献数量。本文拟论证的贡献是：建立可定位瓶颈且可核验等价性的完整流程；在 REAL-Q backward 中实现无损保存张量迁移与副本管理；依据阶段工作集组合已有暂存/分块实现，使收益在完整工作流上成立。第三项必须有独立消融，不能把所有开关合在一起后推断每项都有贡献。

## 工作集模型与瓶颈定位

设进程在时刻 t 的活跃 GPU 张量占用为 A(t)，allocator 已保留的显存为 R(t)，整卡占用为 D(t)。分别报告 max A(t)、max R(t) 和采样得到的 max D(t)。R 包含可复用空闲缓存；D 还包含 CUDA 上下文、库和设备上的其他工作。把数据转移到 CPU 降低的是 GPU 需求，不能称为 CPU+GPU 总内存同幅降低。

单层 hidden size 为 d 时，FP32 Fisher 矩阵存储约为 4d² 字节。MLP 中间维度为 f 时，down-projection 对应的输入二阶矩阵按一组约为 4f² 字节估算。保存激活则依赖 batch、序列长度和具体算子，词表中间量依赖 token 数与词表大小。这些表达式只是组件规模，不能把所有组件相加后当作实测峰值：是否共存取决于执行顺序、缓存策略和释放时机。

Qwen3-0.6B 与 1.7B 的 hidden/MLP 维度分别为 1024/3072 和 2048/6144；上述平方矩阵的单组件规模增加四倍。两模型都含 28 个 Transformer blocks。实验必须记录实际峰值位置，并在相同 batch/序列条件下比较规模变化。0.6B 的 2×1024 和 1.7B 的 2×512 可以分别检验适用性，不能作为控制了序列长度的模型规模因果对照。

## 无损保存张量迁移

autograd 的 backward 需要前向保存值。迁移实现使用 saved-tensors hooks，在 pack 时为符合条件的非叶 CUDA 张量保存 CPU 副本，在 unpack 时恢复到原设备。数据类型和数值保持不变，真实 forward/backward 图仍由原算子执行。当前采用同步复制；它避免引入异步流依赖和预取错误，但可能增加通信等待。

实现入口是 `--static_saved_tensor_offload_mib`，当前对照固定使用已有 4 MiB 阈值。阈值是资源调度条件，不能以搜索一个更好的阈值作为论文核心创新。量化、梯度和抽样条件必须在两侧一致。CPU 驻留、传输量和 GPU 峰值同时记录，以揭示卸载代价。

方法依据是 PyTorch saved-tensors hooks 的接口语义；Capuchin 提供张量迁移和资源管理的相关系统研究。本项目未实现 Capuchin 的完整决策机制，也未证明同步 CPU 卸载会提高速度。

## 版本与视图安全的副本去重

普通卸载可能为不同 backward 节点重复复制同一保存值。参考 SSDTrain 对底层 storage 身份的管理，本实现只复用相同版本、相同存储区域的保存值，不根据相似数据或相同 shape 猜测等价。

缓存键包含 storage 唯一标识、设备、dtype、版本和视图区域。唯一标识随 storage 对象建立，避免裸地址被 allocator 复用。连续同区域允许 reshape 后共享副本，unpack 恢复各自形状；非连续视图另外区分 shape、stride 与 offset。只复制当前视图，不复制整个父 storage。缓存使用 CPU payload 的弱引用，不持有原 GPU tensor；最后一个图引用释放后副本即可释放。

实现位于 `utils/saved_tensor_offload.py`，使用默认关闭的 `--static_saved_tensor_offload_deduplicate`。记录请求字节、实际复制字节、命中次数、活跃 CPU payload 和峰值。累计传输节省、活跃 payload 峰值和进程 RSS 是不同指标。当前未实现 SSD I/O、异步预取、transfer overlap 或 FSDP 权重排除，不将这些文献能力写为已有实现。

## 阶段交接与缓存生命周期

较低的活跃张量占用不保证较低的 reserved。1.7B 的初次阶段实验在 Stage-0 退出时只剩 1024 B 活跃张量，但候选仍保留更多 allocator 缓存。这是工程生命周期问题，不能通过删除测量点消除。

修复在 cache 持久化后的 Stage-0 进程交接处执行一次同步和空闲缓存释放，两侧共享此修复，避免在每个 refresh 中反复清空。前面区间的高水位仍被保留；退出边界另记录释放前后的 allocated/reserved。该操作不释放活跃张量，也不证明其他阶段的峰值已经下降。

## 等价性与显存接受协议

每组对照独立重新生成 Stage-0 cache。两侧记录源码和参数快照、软件环境、设备身份及每 rank 文件，缓存内容按相对路径逐文件计算 SHA-256。完整量化后检查模型权重 state、全部 28 层实际评估输出指纹和最终 KL/PPL。各层必须有真实前向次数和对应 shape；空文件或未执行的 hook 不构成一致性证据。

SHA-256 相同表示本次数据轨迹的逐字节一致，不是对所有可能输入的数学证明。验证依次覆盖函数级真实 CUDA 梯度、实际预计算缓存、完整模型和多次重复；负向结果保留原始证据。浮点实现若不逐位一致，应另立容差与质量协议，而不能沿用本研究的 exact 标签。

精确 allocator 区间测量在同步 marker 处读取高水位并重置区间计数，独立累计整个进程最大值。重复 phase 按 occurrence 分开，避免用一个 batch 的较高值遮住另一个 batch 的回升。最终评估建立独立区间，并在进程返回前补齐全流程高水位。NVML 采用 100 ms 外部采样，主机进程树 RSS 采用 250 ms 采样；报告时间戳缺口和共享页重复计数限制。

本研究接受条件为：正确性通过，完整峰值不增加，全部已测对应区间/同步边界不增加。这个条件不等于证明两个不同执行轨迹在连续时间的每个瞬间都被支配。终稿采用“全局峰值下降、所有已测对应区间与边界无回升”的表述。

## 已确认的初步结果及限制

2026-10-10 三组完整重复已经完成：Qwen3-0.6B 2×1024校准、refresh/final microbatch=1、全部28层、2×1024评估，卸载+去重候选相对关闭卸载对照的 NVML峰值每组都是6469→3499 MiB（−45.91%），完整allocated每组5493.87→2707.62 MiB（−50.72%），reserved5838→2734 MiB（−53.17%）。所有新鲜缓存、权重状态、实际28层输出、KL/PPL精确一致，所有已测区间/边界无回升。这是有重复证据的pilot成果。主机RSS峰值均值6163.27→9893.98 MiB（增加60.54%），必须与GPU收益并列报告。图表及每次原值见 `outputs/figures-qwen06b-full-offload-dedup-threepairs-20261010/`。

对原始NVML时间戳逐段积分，三对全流程时间平均占用减少比例分别为−1.54%、+1.36%、+1.29%，包含初始化/写盘/退出，尚不能主张平均显存减少10%。峰值降低与平均占用降低是不同结论。

Qwen3-1.7B 2×512/完整28层首对的数值也保持精确一致，完整NVML5321→4739 MiB（−10.94%）；但是layer0量化后前向的reserved区间多60 MiB、同步边界多108 MiB，严格门槛失败。因此不能写成两模型都已通过“所有已测阶段不回升”。失败点定位于inactive split；后续缓冲区复用经stride修复后数值一致，但同一个60/108 MiB回升仍存在，未能修复碎片，不作为成功组件。

独立CE256消融首对在已有卸载＋去重基础上，完整28层和最终评估精确一致，NVML3499→3151 MiB（进一步减少9.95%），完整allocated/reserved分别减少16.28%/12.73%，全部已测区间/边界无回升。新的全程allocator峰值迁移至最后一层down_proj Hessian逆分解。这里只有一对；不将历史跨campaign的6469→3151算术拼接当作三组新组合证据。证据见 `outputs/summary-qwen06b-ce256-full-ablation-20261010/`。

另一个完整block non-reentrant重算原型在实际0.6B FSDP Stage-0首对取得6469→2761 MiB（−57.32%），所有Fisher/saliency缓存精确一致，224个观测模块均触发两次梯度钩子；主机RSS基本相同。这只是预计算阶段验证，尚无完整量化/最终质量和重复证据。REAL-Q自身提到checkpoint，所以工程贡献应描述为适配统计钩子、模块身份和系统验证，而不是发明激活重算。

上述Stage-0 pilot之后，另立fresh完整量化实验：两侧共同使用offload_inps，refresh/final microbatch=2，candidate仅整块checkpoint＋评估CE256。新tag `qwen06b-checkpoint-ce-original-input-full-threepairs-20261010-1457` 在15:29完成首对，13个缓存、507个状态tensor、28层输出、KL/PPL均精确一致（0.30534985661506653 / 25.013607025146484），2961个对应阶段条目无区间或边界回升；NVML6461→4247 MiB（−34.27%）。Stage-0 allocated降低至2116059648 B，Stage-2 allocated两侧都是3304098304 B，故全程峰值迁移到末层KL刷新。这个结果不与旧microbatch1的峰值/质量拼接，三对重复仍在运行，以最终status和逐对audit为准。两臂首对NVML各有约1.2秒缺口，时间积分按预设规则拒绝，尚无平均占用结论。

早期0.6B、2×1024校准/评估的普通卸载首对也通过全流程：NVML6469→3499 MiB，主机aggregate RSS约5.92→12.18 GiB。上面的三组是后来加入副本去重的完整组合对照，主机成本较小，但不能把历史不同运行的RSS差值当作组件消融；组件效应以独立匹配的普通卸载/去重卸载阶段对照为准。

在普通卸载与去重卸载的实际 0.6B Stage-0 首对中，累计复制字节减少约 40.01%，主机 aggregate RSS 峰值减少约 19.93%；GPU 峰值保持相同，cache 精确一致。1.7B 的修复后 Stage-0 首对整卡峰值 4867→3301 MiB，退出 reserved 均为 2 MiB，所有已测区间/边界无回升；它尚不能替代完整 1.7B 量化验证。

这些试验共享 FSDP CPU-offload/meta-init、KL chunk16 与 label chunk16；control 是明确约定的系统参考，不是未经修改的论文原始实现。当前结果只量化候选相对共享条件的增量贡献。论文正式校准的 2048×2048、真实四卡及多个独立完整配对仍需补齐。所有诊断 wall times 包含同步、哈希、输出采集和写盘，不作为加速成果。

## 最终实验矩阵与失效处理

1. 两模型按同一算法条件执行新鲜缓存的完整工作流；先检查数值，再接受显存。截至2026-10-11，两模型相同cal2×1024/microbatch2/eval2×1024配置各完成三组，全部数值及已测资源门槛通过。旧配置的首对或前缀结果保留为历史，不混合计算。
2. 逐步增加校准工作集以检验资源门槛。cal8×1024/eval8×1024、seed45的完整配对已排在当前容量实验之后；它仍是本地扩展验证，不是正式2048样本。固定PyTorch分配器预算的完整对照正在进行，OOM作为资源可行性事件单独记录，不能用截断配置产生的输出冒充完整实验，也不能将分配器限额冒充物理小显存卡。
3. 消融关闭迁移、普通迁移、迁移+去重、整块重算；Hinv 暂存和评估分块分别检查。相同组件若作为共享对照条件，不能重复计算收益。
4. 四卡每 rank 的状态、输出、峰值与退出资源验证；命令构造检查不能代替真实多卡运行。
5. 在空闲设备运行每模型至少三组非诊断成本配对，交替顺序，分别报告统计收集和量化的每对原值、均值、范围及软件/设备条件。当前排队的实验测量已接受省显存方案的重计算成本，不是新增速度kernel研究；正式端到端时间还须另测模型准备及评估。不得仅删掉极端值后宣称加速。

如果完整峰值没有下降，先定位迁移后的新瓶颈；如果 reserved 回升，检查活跃值与 inactive split/segment 数据；如果质量不一致，停止后续重复并定位最早不一致的 cache、模块或层。每个修复回到同源码的新鲜配对，不在运行期间更改模型实现。

## 2026-10-10 中午补充：尚未升级为全流程结论的组件

绑定原模块forward的非重入整块checkpoint，保留原模块对象、Fisher hooks和真实两次VJP，Stage-0后恢复forward。0.6B/2×1024与1.7B/2×512各一对实际FSDP的13份缓存精确相同，每侧224个模块各两次梯度hook，全部已测区间/边界显存无回升。整卡Stage-0峰值分别 `6469→2761 MiB` 和 `4867→3301 MiB`，主机RSS接近对照。本结果证明采集阶段的适配正确性，尚不能声称完整流程同幅下降；正在将它与评估CE分块组合后重新执行全部28层、三次0.6B配对。

CE分块单独完整0.6B首对 `3499→3151 MiB`，状态、28层输出与KL/PPL精确相同。但更广函数检查发现旧实现FP64 chunk sum改变原FP32 mean，且小tile/短尾改变CUDA词表归约分支。因此修复为保留原分支及原mean；接入生产函数后72个CUDA用例通过。对应Torch2.11，其他版本必须重新检验。该修复属于无损工作集优化的正确性保障，而不是新的损失算法。

真实FSDP下单独迁移保存的冻结权重没有正向系统收益；关闭backward unshard的组合也增加显存，均保留为负向消融。Hessian CPU分组卸载降低1.7B前缀全程峰值11.47%，但第0层重放阶段reserved区间高出476 MiB，因违反严格约束而拒绝。容量下降与生命周期正确必须同时成立，不能依据局部峰值选择性汇报。
